Android 16 (crDroid) for the **Huawei MateBook E Go** (Snapdragon 8cx Gen 3 /
SC8280XP) on a **mainline Linux kernel**, with hardware Vulkan on the Adreno 690.

The first **release candidate for 1.0**. Compared with v0.7.1-alpha: **release
builds no longer open adb to the network**, **SELinux is enforcing**, the
machine has **its own boot entry that rolls back a failed update by itself**
and a **fastboot mode**, the kernel moves to **7.2.9 stable**, and Wi-Fi keeps
**the same MAC address** across reboots.

## How this candidate was tested

Every "tested on the machine" below was checked on the 1.0 development builds
(1.0.0-dev.1 to dev.10) on the developer's machine. rc.1 is dev.10 plus the
fixes listed under *Chinese input* and *SELinux*.

## Security advisory: network adb on v0.7.1 and earlier

**v0.7.1-alpha and every earlier release let anyone on the same network take
over the machine.** Those images listened for adb on TCP port 5555 on every
network interface — your hotspot included — accepted connections **without**
the "Allow USB debugging?" prompt, were debuggable (so `adb root` gave a root
shell), and carried the maintainer's adb public key.

This build, like every 1.0 release build:

* does not listen on port 5555, and adb is **off** until you turn it on in
  Developer options;
* asks you to authorize every computer (`ro.adb.secure=1`);
* is not debuggable (`ro.debuggable=0`), so `adb root` no longer exists;
* carries no maintainer key.

Nothing to do when you install it: the old port-5555 setting was a built-in
default of the image, and Android does not save those defaults to `/data`.
**The exception is anyone who ran `setprop persist.adb.tcp.port …`
themselves** — that value is stored on `/data` and survives a reinstall with
*Keep user data*.

If you use adb:

* After installing, adb over the network stops working until you set up
  *Wireless debugging* (pairing code) or authorize a computer over USB.
* **An authorized computer still gets a root shell**: root (KernelSU /
  ReSukiSU) is built in, and `adb shell` runs as root through it even though the
  build is not debuggable. Only authorize computers you trust.
* *USB debugging* switches itself back off at every reboot.

## SELinux is enforcing

v0.7.1 and earlier ran SELinux in `permissive` mode: it only logged what its
rules did not allow. **From this build it is `enforcing`** — it blocks those
things, so an app that finds a vulnerability can do much less than before.

Tested on the machine with SELinux enforcing: display, touch, Wi-Fi, sensors,
audio, hardware video decoding (15/15), front and rear cameras, standby and
wake 11/11 (including USB role switching and replugging), and installing a
system update. Two kinds of denials remain in the log, both from stock Android
components (reading the keyboard's country, and a cache of the secure-element
service); they broke nothing in these tests.

**If you partitioned the disk by hand:** under enforcing, Android can only open
the EFI partition when its GPT partition *name* is `esp` (what the installer's
*Erase the whole disk* creates) or `EFI system partition` (what Windows
creates, used by dual boot). With any other name, **switching slots and system
updates fail**. Fix it once from any Linux — the installer's terminal or the
rescue system: `sgdisk -c <N>:esp /dev/nvme0n1` (N = your EFI partition's
number; UEFI only looks at the partition *type*, so renaming is harmless).
The installer warns about this when it sees such a name.

Testing the first update under enforcing turned up a failure (triggered by a
developer tool that kept the EFI partition mounted) that is fixed in this
build: the boot-control service now copes with the EFI partition being mounted
elsewhere, and falls back to finding it by name when it is not allowed to scan
`/dev/block`.

If something worked on v0.7.1 and does not here, please report it with the
output of `adb shell dmesg | grep avc` (see the FAQ for adb).

## The boot entry, automatic rollback and fastboot

**Android now has its own boot loader, gk3boot**, started by systemd-boot as the
default entry `Android`. It reads Android's A/B state in `misc`, picks the slot
and starts that slot's kernel straight from its boot partition — the job a
phone's bootloader does. It takes over after the first boot on this build has
finished (that first boot still goes through the old per-slot entry), and it is
on by default.

* **A broken update rolls back on its own.** A freshly updated slot gets six
  tries; if it never finishes booting, gk3boot goes back to the previous slot and
  Android shows "rolled back to the previous version". Tested on the machine with
  a deliberately broken update that panicked six times in a row. A hang that never
  restarts still needs the power button.
* **A broken loader cannot lock you out.** If the `Android` entry fails to start
  three times, systemd-boot falls back to the old per-slot entry. Tested on the
  machine.
* **fastboot.** `adb reboot bootloader`, `adb reboot fastboot`, or the boot menu
  entry `Android fastboot / boot menu` start a small fastboot environment (cable
  in the USB-C port next to the power button). Checked on the machine:
  `fastboot devices`, `fastboot getvar all`, `fastboot oem device-info`,
  `fastboot reboot`, `fastboot reboot bootloader`, the volume keys in its menu,
  and that `adb reboot bootloader / fastboot / recovery` all land there and a
  pending request is cleared afterwards.

Not tested on the machine yet:

* `fastboot flash` (implemented, passes the emulator tests) — reinstall with the
  graphical installer instead for now.
* Confirming a menu item with the power button in fastboot mode.
* **Factory reset through this path** (see Known issues).
* Dual boot: making Windows the default system, and *Restart to Windows* from the
  new *Boot options* page in Settings.
* The first switch-over on a machine coming from 0.7.x.

To turn it off: as root, `setprop persist.vendor.gaokun3.gk3boot off` and reboot
once; the machine then boots exactly as before 1.0.

## Kernel: 7.2.9 stable

The kernel moves from the 7.2 release candidate (7.2-rc2) to the **7.2.9 stable**
release, with our patches carried over. One stable change broke this machine's
screen — the two halves of the panel are driven together, and 7.2.6 reverted a
fix for exactly that setup, leaving the panel dark. We revert that revert. The
unfinished fingerprint experiment is no longer part of the release kernel (it
never did anything for users).

Tested on this kernel: display, front and rear cameras, hardware video decoding
15/15 with the screen on, standby and wake 11/11 with Wi-Fi back within 2–6
seconds each time.

## Wi-Fi

* **Stable MAC address.** The Wi-Fi chip used to come up with a new MAC address
  on every boot, so routers saw a "new device" each time. The address is now
  derived from the SoC's serial number (a locally administered address) and is
  the same on every boot; tested on the machine, including through 11 standby
  cycles that reload the Wi-Fi firmware. It will differ once from whatever
  address you had before — if your router reserves an IP for the old one, update
  that reservation. Per-network random MAC addresses stay **off**, as before:
  every network sees the same device address.
* **Hotspot and Wi-Fi at the same time** should now work — the driver always
  supported it, the software configuration did not. The second interface the
  hotspot needs is now created at boot (checked on the machine); actually
  connecting another device to the hotspot while Wi-Fi stays up has **not been
  tested yet**.
* **5 GHz and WPA3 for the hotspot** are offered. (Not tested on hardware yet.)
* Network-connectivity checks have fallback endpoints that are reachable in
  mainland China. (Not tested on hardware yet.)
* Time sync tries `ntp.aliyun.com` first and keeps retrying; tested on the
  machine.

## Battery and standby

* **Standby switch in Settings.** *Settings → Battery → Standby (sleep)* turns
  standby off or on ("Allow standby") without a root shell. (Not tested on
  hardware yet.)
* **Charge limit (experimental, off by default).** *Settings → Battery →
  Charging control* can hold the battery at 70–80 %, through Huawei's embedded
  controller (EC). We have **not** tested this on the machine, by decision —
  testing means writing to the EC — so we have not seen how the EC behaves when
  it reaches the limit (whether it then runs the machine from the charger, for
  instance).
* **Battery usage per app** gets a power profile for this machine, so Settings
  can estimate which apps used the battery. The component currents in it are
  estimates. (Not tested on hardware yet.)
* **Sensors stop when the screen is off** and no app needs them; the sensor DSP
  used to stay awake all the time. Tested on the machine.
* **Sensors come back after the sensor DSP crashes.** A new service restarts the
  sensor chain when the DSP recovers from a crash; before, all sensors (and
  auto-rotate) stayed gone until a reboot. (Not tested on hardware yet.)
* Background apps are kept on the four smaller cores (Cortex-A78C, cpu0–3); the
  app in front can still use all eight. The setting is checked on the machine;
  its effect on performance has not been measured.
* The battery status from the embedded controller is decoded in more detail
  (adds a capacity level). Tested that the new values appear; not yet tested
  whether this fixes "charging while draining on a weak charger".

## Audio

* **USB sound cards** are supported by the audio system now. (Not tested on
  hardware yet.)
* **The microphone of a wired headset** should work now. Until that is tested
  on hardware, the known-limitations entry saying it does not work stays.

## USB and storage

* When a USB-C port gets into a bad state, or the tablet ends up powering the
  computer instead of the other way round, Settings shows a notification
  telling you to replug or reboot. (Not reproduced on hardware yet.)
* A mouse or USB stick plugged into the port next to the power button should
  stay connected when the screen turns off. (Not tested on hardware yet.)
* `/data` now keeps a small reserve (128 MiB) for the system, so a full disk
  cannot stop Android from booting. Tested on the machine.

## Chinese input

**A Chinese input method, fcitx5 (pinyin, shuangpin and wubi built in), is
preinstalled** — rc.1 is the first build that really carries it: in the
previous test build Android refused to install it, because the build system
had damaged the app's signature; that is fixed. It is not the default keyboard:
turn it on once in Settings (see known limitations). How a hardware keyboard
switches between Chinese and English has **not been checked yet**.

## New defaults

* **Time zone: Shanghai.** A machine that has never had its time zone set
  (it shows GMT) switches to Shanghai time once this build is installed. A time
  zone you set yourself is kept.
* **Backup: Seedvault** becomes the default backup service — only on a fresh
  install or after wiping data; an existing installation keeps its current
  backup service.

(Neither checked on the machine yet.)

## Smaller things

* **Rear camera privacy light**: the camera's white indicator light now turns on
  while the rear camera is in use, and off when it stops. Tested on the machine.
* The lid state is reported correctly from the first moment after boot (tested
  with the lid open; not yet with the lid closed).
* With the keyboard switched off in Settings, unplugging and replugging the
  keyboard cover keeps it off. (Not tested on hardware yet.)
* The machine no longer claims to have a vibration motor (it has none).
* Apps that check for OpenGL ES 3.2 now see it; the machine no longer claims to
  have a compass; the accelerometer and gyroscope report their real 50 Hz rate.
* System updates clean up unused files on the EFI partition, leaving more room
  for future updates (87 → 104 MB free on the test machine).
* The project version is readable as `getprop ro.vendor.gaokun3.version`.
* The kernel's hung-task watchdog is really on now (120 s).
* A failed backlight write no longer crashes the system UI. (The original crash
  was not reproduced on purpose.)
* The audio/Bluetooth hang watchdog records more evidence (stalled playback,
  DSP state changes).
* The update screen's *changelog* and *download* links now point to a mirror
  reachable from mainland China.
* The graphics device node is no longer world-writable.

## Graphical installer

The installer attached to this pre-release (`0.2.0-rc.1`) is
needed to install rc.1 (see the top). New since the `0.1.0-preview` installer
of v0.7.0:

* **A risk notice you have to read before anything is written to the disk**:
  scroll to the end, wait 15 seconds, tick that you have backed up your data;
  erasing the whole disk, or editing a disk that has Windows on it, also asks
  you to type `ERASE`.
* **Disks it cannot handle are refused up front**: an MBR (non-GPT) disk can
  only be erased as a whole, and a disk whose partition table cannot be read is
  shown as such and cannot be selected — before, the installer could fail
  half-way on them.
* **Dual boot**: the confirmation page asks which system starts by default
  (Android is preselected); it asks you to confirm you have the BitLocker
  recovery key when the Windows drive is encrypted. The installer refuses to
  touch a hibernated Windows, or an EFI partition that is too small (under
  200 MiB).
* **While it writes to the disk**, the power button and closing the lid no
  longer shut down or suspend the machine.
* **Downloads** can be cancelled, and a failed one resumes where it stopped
  when you retry; after a failure the logs can be saved to a USB stick.
* **Windows companion (preview)**: the Windows script now also installs itself
  on Windows, with a *gaokun3* Start menu folder (restart into Android, choose
  the default system, repair the Android boot entry, remove Android) and a check
  at every Windows start that warns if Windows replaced the boot loader (see
  INSTALL).

All of this was tested only on test disks (containers, loop devices) and in
automated tests — the Windows script in a Windows virtual machine, the
companion only in its own test suite — **not on this machine**: this installer
version has not run on real hardware yet.

## Known issues

* **Do not tap *Erase all data* in Settings unless you mean it — and do not rely
  on it either.** Earlier releases ignored it. In this build the new boot entry
  is expected to carry it out (erase `/data` and restart into the setup wizard);
  every step up to the actual erase was tested on the machine, but the erase
  itself has not been, and is not planned to be before 1.0. To wipe the machine
  reliably, use the graphical installer's *Reinstall Android*.
* **Machines where Windows was deleted by hand** may still show *Restart to
  Windows* (Settings → System → Boot options) and a Windows entry in the boot
  menu: Windows' boot files are still on the EFI partition. Choosing it will
  not boot anything useful. Disks set up by the installer's *Erase the whole
  disk* are not affected.
* **System updates and slot switching fail** on hand-partitioned disks whose
  EFI partition has a non-standard name — see *SELinux is enforcing* above for
  the one-line fix.
* The new features listed above as "not tested on hardware yet" are exactly
  that; reports are welcome.

## Known limitations

The full list, with workarounds, is in
**[docs/known-limitations.md](https://github.com/vahiru/gaokun-android/blob/main/docs/known-limitations.md)**
([中文](https://github.com/vahiru/gaokun-android/blob/main/docs/known-limitations.zh-CN.md)). In short:

* **Security**: signed with Android's public test keys; `/data` is **not
  encrypted**; root (KernelSU / ReSukiSU) is built in, and any computer you
  authorize for adb gets a root shell; SELinux is `enforcing` from this build,
  but on a hand-partitioned disk the EFI partition may need renaming (see
  above); the boot chain is unlocked. Network adb without authorization on
  v0.7.1 and earlier: see the advisory above.
* **Proprietary components** ship in the images: Huawei firmware and sensor
  configuration, the Huawei Histen audio engine, and Google apps (MindTheGapps).
* **Not supported**: *Erase all data* in Settings (see Known issues; use the
  graphical installer's *Reinstall Android*); file transfer over USB (MTP); USB
  sticks; fingerprint (in progress); stylus (M-Pencil); automatic brightness;
  GPS / location; DRM video (no Widevine); the microphone of Bluetooth headsets
  in calls, and of wired headsets; push notifications while in standby; Google
  certification (register once; Play Integrity never passes); no Chinese app
  store; no cellular network; no compass.
* **Other problems**: audio and Bluetooth can hang after a long uptime; plugged
  into a computer, the tablet may charge the computer instead; the USB-C port can
  stop working after replugging until a reboot; a palm on the screen turns into
  several touches; *Wild Rift* closes right after launch; on a weak charger the
  battery says *charging* while it drains; turning on the hotspot disconnects
  Wi-Fi (a fix is in this build, see *Wi-Fi*, not yet tested). The Chinese input
  method (fcitx5) is preinstalled but has to be turned on once in Settings.
