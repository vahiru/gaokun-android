**Android 17 (crDroid 13)** for the Huawei **MateBook E Go** (Snapdragon 8cx Gen 3 / SC8280XP), running on a **mainline Linux kernel**,
with hardware Vulkan on the Adreno 690.

**The third 1.0 release candidate, and first of all a security fix.** Every earlier version writes the kernel log into the
firmware's variable storage (NVRAM) on every kernel crash and never cleans it up; once the storage is full, **USB sticks and
the official recovery image can no longer boot** ([#56](https://github.com/vahiru/gaokun-android/issues/56)). This version
stops writing. It also **moves from Android 16 to Android 17** and brings speaker, auto-brightness, touch and stylus improvements.

**Community:** [Telegram](https://t.me/gaokunAndroid) · QQ group **920133252**

> ### ⚠️ Read this: the fix only stops new writes; clean up existing records once yourself
> After updating, check once as described in [#56](https://github.com/vahiru/gaokun-android/issues/56) or the
> [FAQ](https://github.com/vahiru/gaokun-android/blob/v1.0.0-rc.3/docs/FAQ.md#booting-and-the-boot-menu).
> If USB sticks stopped showing up in the boot menu, **the mainboard is not broken and does not need replacing**; deleting the records fixes it.
>
> ### ⚠️ This is a major upgrade (Android 16 → 17)
> **Users of rc.2, rc.1 and v0.7.1-alpha all get this version in System update.** **Back up first**: Android 17 upgrades
> the data in `/data` on its first boot, and `/data` on this machine has no rollback point. If the update does not boot,
> the boot menu still offers the previous Android entry (needs a keyboard), but the old system may not boot on data the new
> one has already changed; you may need to wipe data or reinstall with the graphical installer.
> System update shows this version as a normal Android 16 update; that is what lets the older updater accept it. Once
> installed, it is Android 17.
>
> A fresh install **erases the internal disk** (except in the installer's dual-boot mode). You need to be able to rescue a
> machine that does not boot. No warranty. Secure Boot must be off.

## How this candidate was tested

On 2026-10-30, build `1793322048` (incremental `20261030010048`) was installed by OTA into the development device’s inactive slot and booted with a one-shot entry, with SELinux Enforcing. A-tier acceptance: **46 PASS / 0 FAIL / 2 WARN / 0 SKIP**, including both cameras, microphone, GPU and hardware decoding. The warnings concern uptime below ten minutes and the existing A17 InputReader `country` / gpuservice BPF attribute-query denials.

On-device verification: `efi_pstore.pstore_disable=Y`, pstore backend `(null)`; the EFI writer is not registered. The development device’s persistent TCP adb setting was temporarily disabled for acceptance. The upgrade tested here was A17 → A17; **A16 → A17 OTA was not rehearsed again**.

Hardware decoder regression: **15/15 PASS**, covering AVC / HEVC / VP9 seek, end-of-stream, stop, drain and resolution changes; zero iris errors. Both camera smoke tests passed again afterward.

## Security fix: firmware storage filled with crash records

* The kernel no longer writes crash logs into firmware variables (boot parameter `efi_pstore.pstore_disable=1`, and off by
  default in the kernel config). The cost is that a kernel crash no longer leaves a record behind, so when reporting a
  freeze, please describe what you were doing.
* Records that are already stored are not deleted automatically; clean them up once as described in #56.

## Android 17

* The system moves from crDroid 12 (Android 16) to **crDroid 13 (Android 17)**, security patch level 2026-10-01.
* The graphics driver (Mesa / Turnip) moves to 26.1 with it. A hardware HEVC decoding regression on Android 17 is fixed.

## Speakers

* **Fixed the heavily compressed dynamic range and distortion at high volume** (amplifier port mapping, dynamic DRE, bus clash).
* **Speaker enhancement** now lives in the audio HAL, so everything played on the speakers is processed, games included.
  Settings offers **bass enhancement** (default) or **Huawei Histen**.

## Display

* **Auto-brightness works**: the ambient light sensor is now supported and auto-brightness is on by default.

## Touch and stylus

* Fixed taps occasionally being lost and touches starting at the screen edge being dropped entirely; touch-down is reported
  one frame earlier, and swipes are steadier, without jitter or lag.
* In rhythm games, fast taps are no longer merged into the finger that has just lifted.
* **Stylus** positions are smoothed and reported with sub-pixel precision, so strokes are no longer jagged when zoomed in.

## Known issues

Unchanged from rc.2; see [known limitations](https://github.com/vahiru/gaokun-android/blob/v1.0.0-rc.3/docs/known-limitations.md).
