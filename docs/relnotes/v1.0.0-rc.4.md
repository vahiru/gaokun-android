**Android 17 (crDroid 13)** for the Huawei **MateBook E Go** (Snapdragon 8cx Gen 3 / SC8280XP), running on a **mainline Linux kernel**,
with hardware Vulkan on the Adreno 690.

**The fourth 1.0 release candidate.** Compared with 1.0.0-rc.3: the cameras move from the software ISP to Qualcomm's **IFE hardware ISP** with 1080p Camera1 recording, zoom and exposure controls; the SoC enters **deep standby** (~0.5 W) and **wakes on FCM push notifications**; the display gains **factory 3D LUT colour calibration**, **HDR video boost**, and **automatic BOE / CSOT panel detection** in a single image; video adds **10-bit hardware decoding** and **H.264 / HEVC hardware encoding**; audio adds **four-microphone beamforming, call echo cancellation and NPU noise suppression**, lower game latency, and a wired-headphone fix; the **side fingerprint sensor** works for screen unlock; and the GPU gets a **kernel crash fix** and **Adreno 690 preemption**.

(If you are still on v0.7.1-alpha, rc.1 or rc.2, read the [rc.3 release notes](v1.0.0-rc.3.md) first for the Android 16 → 17 `/data` upgrade and the one-time firmware crash-record cleanup from [#56](https://github.com/vahiru/gaokun-android/issues/56).)

> * **USB / adb serial number**: the tablet now reports its real SMBIOS serial number over USB instead of the fixed string `gaokun3`.
>
> A fresh install **erases the internal disk** (unless you use dual-boot mode), and no image of the factory state exists anywhere. You should be comfortable recovering a machine that will not boot. No warranty.

## Camera

* **Switched to the IFE hardware ISP** ([#120](https://github.com/vahiru/gaokun-android/pull/120); initial IFE pixel-path patches by **@dezige131**): demosaicing, white balance, colour correction, gamma, scaling and focus statistics now run on Qualcomm's IFE hardware instead of the CPU, and the software ISP path has been removed.
  * Rear binned mode reaches up to **60 fps** (full-resolution rear and front run at 30 fps); full-resolution preview and still capture use separate IFE outputs, cutting camera service CPU usage from ~48% of a core to ~21%, and JPEG encoding runs on its own thread so taking a photo no longer pauses the viewfinder.
  * Added IFE digital zoom, phase-detection autofocus refined by contrast search (falling back to IFE focus statistics in dim light), exposure compensation, AE/AWB lock, manual exposure and focus, white balance presets, 50/60 Hz anti-banding, luma sharpening, still-photo denoising, and JPEG EXIF metadata with thumbnails.
* **Orientation, frame rate and Camera1 apps** ([#83](https://github.com/vahiru/gaokun-android/pull/83), [#86](https://github.com/vahiru/gaokun-android/pull/86), [#87](https://github.com/vahiru/gaokun-android/pull/87), [#91](https://github.com/vahiru/gaokun-android/pull/91), [#115](https://github.com/vahiru/gaokun-android/pull/115); [#42](https://github.com/vahiru/gaokun-android/issues/42), thanks to **@mashen11**): fixed front and rear cameras rotated by 90° (verified on a 2023 unit; 2022 units still need checking), kept indoor front-camera preview at 30 fps, fixed Camera1 support so apps such as QQ can open the camera, and added `media_profiles_V1_0.xml` so Camera1 apps can record up to **1080p** instead of 320×240.

## Standby and Wi-Fi

* **SoC deep standby** ([#80](https://github.com/vahiru/gaokun-android/pull/80), [#90](https://github.com/vahiru/gaokun-android/pull/90)): AOSS, the CX power domain and DDR previously stayed awake during sleep. PCIe root ports now enter D3, the Bluetooth UART releases its clocks and votes on suspend, both PCIe controllers retrain in parallel on resume (with link retries for NVMe), and CPU cluster power-down waits 3 ms before retrying when firmware refuses. Overnight standby measured ~0.51 W (~1.2%/h) on a test kernel; full overnight measurement on the merged release build has not been re-run yet.
* **Timely FCM push notifications in sleep** ([#81](https://github.com/vahiru/gaokun-android/pull/81), [#88](https://github.com/vahiru/gaokun-android/pull/88), [#89](https://github.com/vahiru/gaokun-android/pull/89), [#93](https://github.com/vahiru/gaokun-android/pull/93)): Wi-Fi can now wake the SoC over PCIe `WAKE#`, and a new vendor service (`gaokun3_wifiwake`) installs packet wake filters for Google's push servers so apps using FCM deliver messages promptly while the screen is off. Suspending with WoWLAN no longer drops the Wi-Fi link, and plugging in a charger during deep sleep wakes the system.
* **Crash recovery and long-standby fixes** ([#73](https://github.com/vahiru/gaokun-android/pull/73), [#76](https://github.com/vahiru/gaokun-android/pull/76), [#77](https://github.com/vahiru/gaokun-android/pull/77), [#79](https://github.com/vahiru/gaokun-android/pull/79)): hardened `ath11k` and `mac80211` firmware crash recovery so a second crash during recovery no longer turns Wi-Fi off; stopped staying awake an extra minute on every wake-up after a firmware crash with Wi-Fi disabled; reduced per-address NTP timeout from 5 s to 2 s; fixed a FastRPC context leak on process freeze that kept `hexagonrpcd-sdsp` (sensors) from starting after ~6 hours of standby; and stopped a failed internal xHCI USB controller from aborting every suspend attempt.

## Display and video

* **BOE and CSOT panels share one image** ([#58](https://github.com/vahiru/gaokun-android/pull/58)): the kernel reads the mainboard's panel ID pins (`GPIO102` / `GPIO91`) to pick the matching panel timing, so BOE machines no longer need a separate device tree. (Verified on BOE; CSOT pin reading `0 0` follows the hardware design and awaits confirmation on a CSOT machine.)
* **Factory colour calibration and colour modes** ([#61](https://github.com/vahiru/gaokun-android/pull/61), [#114](https://github.com/vahiru/gaokun-android/pull/114)): loads each tablet's per-unit factory calibration from firmware into the display post-processing block as a 3D LUT, fixes two DPU colour-matrix programming bugs, enables Display P3 and 10-bit output, and adds **Vivid** (default) and **Standard** under *Settings → Display → Colors*.
* **HDR video** ([#62](https://github.com/vahiru/gaokun-android/pull/62), [#65](https://github.com/vahiru/gaokun-android/pull/65)): boosts panel brightness and scales down SDR UI white during HDR playback so highlights can exceed UI white, and declares HDR10 and HLG on the built-in display as well as Main10 HDR10 on the HEVC decoder. Because the LCD backlight is not locally dimmed, dark regions also lift when the backlight rises.
* **Window blur and landscape boot** ([#57](https://github.com/vahiru/gaokun-android/pull/57), [#82](https://github.com/vahiru/gaokun-android/pull/82)): restored background blur on the lock screen, notification shade and Quick Settings, and set the boot animation and initial post-boot orientation to landscape.
* **10-bit hardware decoding and playback fixes** ([#59](https://github.com/vahiru/gaokun-android/pull/59), [#60](https://github.com/vahiru/gaokun-android/pull/60)): added HEVC Main10 and VP9 Profile 2 hardware decoding and display; fixed mpv-based players (such as PiliPlus) falling back to software decoding on every start, decoder service crashes in byte-buffer mode, hardware decoding staying unavailable until a restart after a firmware watchdog reset, and 8 extra lines at the bottom of 1080p video.
* **Hardware video encoding** ([#116](https://github.com/vahiru/gaokun-android/pull/116), [#118](https://github.com/vahiru/gaokun-android/pull/118), [#106](https://github.com/vahiru/gaokun-android/issues/106)): camera recording, `screenrecord` and app video encoding now use the `iris` H.264 / HEVC hardware encoder, including non-16-aligned heights such as 640×480 and 800×480. See *Known issues* for screen-off and single-stream limits.

## Audio

* **Microphone array, echo cancellation and AI noise suppression** ([#70](https://github.com/vahiru/gaokun-android/pull/70), [#84](https://github.com/vahiru/gaokun-android/pull/84)): fixed impulse noise on the built-in microphones (switching the DMIC clock from 4.8 MHz to 3.2 MHz), start-of-recording clicks and missing low frequencies, and raised capture gain. Recordings now capture four channels and apply fixed beamforming across the three top microphones; voice and video calls run WebRTC AEC3 to cancel speaker echo (fixing the echo the other party heard on speakerphone) followed by DeepFilterNet3 noise suppression on the CDSP NPU. Noise suppression defaults to on for calls and off for voice and video recording, configurable under *Settings → Sound & vibration → Microphone noise suppression*.
* **Lower game audio latency** ([#110](https://github.com/vahiru/gaokun-android/pull/110), [#117](https://github.com/vahiru/gaokun-android/pull/117)): reduced speaker ALSA playback buffering from 4 × 480 frames (40 ms) to 3 × 240 frames (15 ms) and HAL playback blocks to 5 ms, cutting game audio latency by ~32 ms in total.
* **Wired headphones** ([#119](https://github.com/vahiru/gaokun-android/pull/119)): disabled the RX macro compander on the headphone route and switched the headphone amplifier to Class AB mode so quiet signals are no longer lifted by ~20 dB.

## GPU

* **Kernel crash fix** ([#112](https://github.com/vahiru/gaokun-android/pull/112)): backported five Linux 7.3-rc1 `drm/msm` fixes for a bug where any process able to open the GPU render node could access the GPU address space before it was created and trigger a kernel null-pointer crash and reboot.
* **Adreno 690 preemption** ([#113](https://github.com/vahiru/gaokun-android/pull/113)): enabled GPU preemption so SurfaceFlinger composition can preempt in-flight game submissions, substantially reducing whole-screen frame drops under heavy GPU load (missed SurfaceFlinger refreshes in *Project SEKAI* dropped from 3.57/s to 0.2–0.45/s).

## Touch, stylus and keyboard cover

* **Stylus accuracy and settings** ([#67](https://github.com/vahiru/gaokun-android/pull/67), [#74](https://github.com/vahiru/gaokun-android/pull/74), [#75](https://github.com/vahiru/gaokun-android/pull/75), [#78](https://github.com/vahiru/gaokun-android/pull/78); CSOT strong-peak selection from **@Rivarise** in [#63](https://github.com/vahiru/gaokun-android/pull/63)): compensated column readout skew and skipped unrefreshed frames to reduce diagonal wobble and fixed-position kinks; enabled skew compensation, strong-peak selection and factory column-pitch mapping on CSOT panels so strokes near the left and right edges no longer drift inward; and added *Settings → Connected devices → Stylus settings* with four ink-smoothing levels and configurable double-tap behaviour (toggle eraser, side-button click, or off).
* **Touch tap and lift** ([#68](https://github.com/vahiru/gaokun-android/pull/68)): tap-lock now considers signal strength alongside step size so taps are less likely to turn into short swipes, and touch-up is reported as soon as firmware sees no finger instead of three frames later.
* **Cover sleep and first-key wake** ([#71](https://github.com/vahiru/gaokun-android/pull/71), [#72](https://github.com/vahiru/gaokun-android/pull/72)): closing the cover turns the screen off, opening it wakes the tablet, and alarm or network wake-ups while the cover is closed no longer light the screen (existing installs migrate `lid_behavior` from 0 to 1 once at boot). Resume no longer resets the keyboard and stylus MCU, so the first key press wakes the screen.

## Fingerprint

* **Side fingerprint sensor** ([#92](https://github.com/vahiru/gaokun-android/pull/92), [#123](https://github.com/vahiru/gaokun-android/pull/123)): added the kernel TA transport driver and userspace AIDL fingerprint HAL, supporting both Goodix GDIX5125 and FocalTech FTE7001 sensors in the same image via board strap detection, plus a SystemUI lockout patch so temporary lockouts pause authentication requests properly. See *Known issues* for security-tier and FocalTech limits.

## Smaller things

* **Per-app kernel version spoofing** ([#69](https://github.com/vahiru/gaokun-android/pull/69)): only regular apps read the disguised kernel version while `uname -r`, Settings and system components see the real Linux version; can be turned off or edited in *Settings → System → Kernel version spoofing* (on by default).
* **5-second boot menu** ([#96](https://github.com/vahiru/gaokun-android/pull/96)): shortened the single-boot Android `systemd-boot` timeout from 15 s to 5 s (matching dual-boot), migrating existing `timeout 15` entries automatically during OTA.
* **Second USB-C port fix** ([#66](https://github.com/vahiru/gaokun-android/pull/66), [#53](https://github.com/vahiru/gaokun-android/issues/53), thanks to **@Rivarise**): kept `vreg_l4b` always on so USB 2.0 on the second port no longer freezes after Type-C reconfiguration.
* **Battery temperature, device serial number, BTF and userfaultfd** ([#97](https://github.com/vahiru/gaokun-android/pull/97), [#98](https://github.com/vahiru/gaokun-android/pull/98), [#99](https://github.com/vahiru/gaokun-android/pull/99)): the battery driver now reports real temperature instead of 0 °C; `ro.serialno` and the USB/adb serial number use the machine's SMBIOS serial instead of `gaokun3`; and kernel `CONFIG_DEBUG_INFO_BTF` and `CONFIG_USERFAULTFD` are enabled so `timeInState`/`dmabufIter` BPF programs load and ART uses userfaultfd garbage collection.
* **Windows installer 0.1.0** ([#121](https://github.com/vahiru/gaokun-android/pull/121)): a standalone graphical installer that installs or removes dual-boot Android directly from Windows 11 without a USB stick, published separately under [`windows-installer-v0.1.0`](https://github.com/vahiru/gaokun-android/releases/tag/windows-installer-v0.1.0).

## Known issues

* **Hardware video encoding with the screen off**: if recording, exporting or compressing video continues after the screen turns off, the video hardware may hang, leaving the clip incomplete and causing subsequent recordings to fail until a restart. Keep the screen on while encoding. Only one stream uses hardware encoding at a time, and the built-in screen recorder at 120 Hz still uses software encoding.
* **Fingerprint limits**: the fingerprint HAL reports Class 1 (convenience), so fingerprint payment in payment and banking apps will not work; pixel-pitch scaling for FocalTech FTE7001 has not been calibrated with real fingers yet, so recognition on FocalTech units has not been verified on hardware.
* **Deep standby caveats**: each sleep cycle powers down the NVMe SSD (its long-term wear impact has not been measured, and 20+ cycle testing on non-Phison SSDs is still pending). If the internal USB controller occasionally stops responding during deep standby, the tablet can still sleep ([#73](https://github.com/vahiru/gaokun-android/pull/73)), but the keyboard cover and stylus require a restart to recover.

## Known limitations

The full list, with workarounds, is in
**[docs/known-limitations.md](https://github.com/vahiru/gaokun-android/blob/v1.0.0-rc.4/docs/known-limitations.md)**
([中文](https://github.com/vahiru/gaokun-android/blob/v1.0.0-rc.4/docs/known-limitations.zh-CN.md)). In short:

* **Security**: signed with Android's public test keys; `/data` is **not encrypted**; root (KernelSU / ReSukiSU) is
  built in; the boot chain is unlocked.
* **Proprietary components** ship in the images: Huawei firmware and device calibration data, the Huawei Histen audio
  engine, Qualcomm's QNN runtime (for microphone noise suppression), and Google apps (MindTheGapps).
* **Not supported or incomplete**: *Erase all data* in Settings (untested; use the graphical installer's *Reinstall Android*);
  fingerprint payment (screen unlock only); first-generation M-Pencil; GPS / location; DRM video (no Widevine); Bluetooth headset
  microphone in calls; push notifications from apps that do not use FCM while in standby; Google certification
  (register once; Play Integrity never passes).
