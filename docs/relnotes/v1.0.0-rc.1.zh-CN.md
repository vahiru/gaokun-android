## 这个候选版是怎么测的

下面每一处"在本机测过"，都是在 1.0 的开发构建（1.0.0-dev.1 到 dev.10）上、在开发者的机器上测的；具体是哪一版写在本说明的源码注释里。
rc.1 = dev.10 加上*中文输入法*与 *SELinux* 两节里说的修复。rc.1 本身的结果：⬜ 验收后补上。

## 安全公告：v0.7.1 及更早版本的网络 adb

**v0.7.1-alpha 及之前的每一个版本，都能让同一网络里的任何人接管这台机器。** 那些镜像在所有网卡上
（包括你开的热点）监听 TCP 5555 端口的 adb，连接时**不弹**"允许 USB 调试吗？"的授权框；镜像是可调试的
（`adb root` 就能拿到 root shell）；镜像里还带着维护者的 adb 公钥。

这一版和所有 1.0 发布构建一样：

* 不再监听 5555 端口，adb 默认**关闭**，要你自己在开发者选项里打开；
* 每台电脑都要你授权（`ro.adb.secure=1`）；
* 不可调试（`ro.debuggable=0`），不再有 `adb root`；
* 不带维护者的公钥。

装上就生效，不用做什么：原来的 5555 设置是镜像内置的默认值，Android 不会把这种默认值存进 `/data`。
**例外是自己运行过 `setprop persist.adb.tcp.port …` 的人** —— 那个值存在 `/data` 上，用*保留用户数据*重新安装后还在。
怎么清掉它，会补在已知限制页面里（⬜ 待上机核实）。

用 adb 的话还要知道：

* 装上之后，网络 adb 会连不上，直到你设置好*无线调试*（配对码）或者通过 USB 给电脑授权。
* **已授权的电脑仍然直接拿到 root shell**：系统内置了 root（KernelSU / ReSukiSU），即使不可调试，
  `adb shell` 也经它以 root 运行。只给你信任的电脑授权。
* *USB 调试*每次重启都会自己变回关闭（⬜ 待上机确认）。

## SELinux 改为 enforcing

v0.7.1 及更早的版本里 SELinux 是 `permissive`（宽容）模式：规则不允许的事它只记录、不拦截。
**从这一版起是 `enforcing`** —— 会真的拦下来，所以一个 App 即使找到了漏洞，能做的事也比以前少得多。

在 enforcing 下在本机测过：显示、触摸、Wi-Fi、传感器、音频、硬件视频解码（15/15）、前后摄像头、
待机与唤醒 11/11（含 USB 角色切换与回插），以及装一次系统更新。日志里还剩两类拒绝记录，都来自 Android 自带的组件
（读键盘的国家代码、安全元件服务的一个缓存）；在这些测试里没有弄坏任何东西。

**如果你的硬盘是自己手动分的区：** 在 enforcing 下，Android 只有在 EFI 分区的 GPT 分区*名*是 `esp`
（安装器"清除整个磁盘"建的就是这个名字）或 `EFI system partition`（Windows 建的，双系统用的就是它）时才打得开它。
别的名字下，**切换槽位和系统更新都会失败**。在任意一个 Linux 里修一次就好 —— 安装器的终端或者救援系统都行：
`sgdisk -c <N>:esp /dev/nvme0n1`（N = 你的 EFI 分区的分区号；UEFI 只看分区*类型*，改名无害）。
安装器看到这种名字时会提醒。

在 enforcing 下第一次测试更新时查出一个失败（由一个一直挂着 EFI 分区的开发工具触发），这一版已经修好：
启动控制服务现在能认出已经挂在别处的 EFI 分区，并且在不允许扫描 `/dev/block` 时改为按名字找它。

如果某个功能在 v0.7.1 上好用、在这里不行，请报告，并附上 `adb shell dmesg | grep avc` 的输出（adb 怎么设置见常见问题）。

## 启动入口、自动回退与 fastboot

**Android 有了自己的启动器 gk3boot**，由 systemd-boot 作为默认项 `Android` 启动。它读 Android 存在 `misc`
里的 A/B 状态、选出槽，直接从那个槽的 boot 分区启动内核 —— 也就是手机上 bootloader 干的活。
它在装上这一版后的第一次开机完成之后接手（那第一次开机仍然走旧的、按槽的条目），默认打开。

* **更新坏了会自己退回。** 刚更新的槽有六次机会；如果始终没能开机完成，gk3boot 会退回上一个槽，
  Android 弹出"已自动退回旧版本"。在这台机器上用一个故意弄坏、连续 panic 六次的更新测过。
  卡死不动、也不重启的情况，仍然要长按电源键。
* **启动器自己坏了也锁不住你。** `Android` 条目连续三次启动失败，systemd-boot 就回落到旧的按槽条目。在本机测过。
* **fastboot。** `adb reboot bootloader`、`adb reboot fastboot`，或者开机菜单里的 `Android fastboot / boot menu`，
  会启动一个小的 fastboot 环境（数据线插靠近电源键的 USB-C 口）。在本机核对过：`fastboot devices`、`fastboot getvar all`、
  `fastboot oem device-info`、`fastboot reboot`、`fastboot reboot bootloader`、菜单里的音量键，以及
  `adb reboot bootloader / fastboot / recovery` 都会进到这里、之后挂着的请求会被清掉。

还没在本机上测过：

* `fastboot flash`（已实现，模拟器测试通过）—— 目前请改用图形安装器重新安装。
* 在 fastboot 模式里用电源键确认菜单项。
* **经这条路恢复出厂**（见"已知问题"）。
* 双系统：把 Windows 设成默认系统，以及设置里新的*启动选项*页上的"重启到 Windows"。
* 从 0.7.x 过来的机器第一次切换过来的那一跳。

关掉它：以 root 身份 `setprop persist.vendor.gaokun3.gk3boot off`，重启一次；之后机器和 1.0 之前完全一样地启动。

## 内核：7.2.9 稳定版

内核从 7.2 的候选版（7.2-rc2）换成 **7.2.9 稳定版**，我们的补丁都带了过去。稳定版里有一个改动弄坏了这台机器的屏幕 ——
这块面板的两半是一起驱动的，而 7.2.6 撤掉了恰好针对这种接法的一个修复，面板就不亮了。我们把那次撤销再撤回来。
没做完的指纹实验已经不在发布内核里了（它从来没给用户带来过任何功能）。

在这个内核上测过：显示、前后摄像头、亮屏时硬件视频解码 15/15、待机与唤醒 11/11、每次 Wi-Fi 都在 2–6 秒内回来。

## Wi-Fi

* **MAC 地址固定了。** 以前 Wi-Fi 芯片每次开机都换一个新 MAC，路由器每次都当成"新设备"。现在地址由 SoC 的序列号派生
  （本地管理地址），每次开机都相同；在本机测过，包括 11 次会重新加载 Wi-Fi 固件的待机。它会和你以前的地址不同一次 ——
  如果路由器给旧地址保留了 IP，请改一下保留规则。和以前一样**不开**按网络随机的 MAC：每个网络看到的都是同一个设备地址。
* **热点和 Wi-Fi 应该能同时开了** —— 驱动一直支持，是软件配置不支持。热点要用的第二个网卡现在开机就建好了（在本机核对过）；
  真的让另一台设备连上热点、同时 Wi-Fi 不断，**还没测过**。
* 热点可以选 **5 GHz 和 WPA3**。（还没在真机上测过）
* 联网检测加了国内能访问的备用地址。（还没在真机上测过）
* 对时先试 `ntp.aliyun.com`，失败后会一直重试；在本机测过。

## 电池与待机

* **设置里有了待机开关。** *设置 → 电池 → 待机（睡眠）*里的"允许待机"，不用 root shell 就能开关待机。（还没在真机上测过）
* **充电上限（实验性，默认关）。** *设置 → 电池 → 充电控制*可以经华为的嵌入式控制器（EC）把电量保持在 70–80%。
  按决定我们**没有**在本机上测它 —— 测它就要写 EC —— 所以也没看过 EC 到达上限时具体怎么表现（例如会不会改由充电器直接给机器供电）。
* **按应用统计耗电**：加了这台机器的功耗参数表，设置里能估算各个应用用了多少电。表里的部件电流是估算值。（还没在真机上测过）
* **息屏且没有应用需要时，传感器会停下来**；以前传感器 DSP 一直醒着。在本机测过。
* **传感器 DSP 崩溃后传感器能回来。** 新加的服务会在 DSP 从崩溃中恢复后重启传感器链；以前所有传感器（连同自动旋转）都会一直没有，直到重启。（还没在真机上测过）
* 后台应用限制在四个小核上（Cortex-A78C，cpu0–3）；前台应用仍然可以用全部八个核。设置本身在本机核对过，对性能的影响没量过。
* EC 报的电池状态解码得更细了（多了电量等级）。测过新值能出来；"弱充电器上显示充电、电量却在掉"有没有因此修好，还没测。

## 图形安装器

装 rc.1 要用这个 pre-release 附带的安装器（⬜ 版本号待填），见开头。相对 v0.7.0 附带的 `0.1.0-preview` 安装器，新增了：

* **写盘前必须读完的风险提示**：滚到最后、等 15 秒、勾选"我已备份重要数据"；清除整个磁盘，或者手动调整一块有 Windows 的盘时，还要输入 `ERASE`。
* **处理不了的盘一开始就拒绝**：MBR（非 GPT）的盘只能整盘清除；读不出分区表的盘会标出来、不能选 —— 以前安装器可能在这些盘上做到一半才失败。
* **双系统**：确认页会问开机默认进哪个系统（预选 Android）；Windows 盘加密时要你确认已经拿到 BitLocker 恢复密钥。
  安装器拒绝动处于休眠状态的 Windows，也拒绝太小的 EFI 分区（小于 200 MiB）。
* **写盘期间**，按电源键、合上盖子都不会再让机器关机或挂起。
* **下载**可以取消；失败后重试会从断开的地方接着下；失败之后可以把日志存到 U 盘上。

## 已知问题

* **除非你真想清空，否则别点设置里的"清除所有数据"—— 也别指望靠它清空。** 以前的版本会无视它。
  这一版里，它应该会由新的启动入口执行（清掉 `/data`，重启进开机向导）；直到真正擦除之前的每一步都在本机测过，
  但擦除本身还没测过，1.0 之前也不打算测。要可靠地清空机器，请用图形安装器的*重新安装 Android*。
* **手动删掉 Windows 的机器**上，可能仍然会看到"重启到 Windows"（设置 → 系统 → 启动选项）和开机菜单里的 Windows 项：
  Windows 的启动文件还留在 EFI 分区上。选它也启动不了什么有用的东西。用安装器"清除整个磁盘"装的盘不受影响。
* **手动分区、EFI 分区名字不标准的盘上，系统更新和切换槽位会失败** —— 一行命令的修法见上面"SELinux 改为 enforcing"一节。

## 已知限制

完整清单和应对办法见 **[docs/known-limitations.zh-CN.md](https://github.com/vahiru/gaokun-android/blob/main/docs/known-limitations.zh-CN.md)**
（[English](https://github.com/vahiru/gaokun-android/blob/main/docs/known-limitations.md)）。简要来说：

* **安全**：用 Android 公开的测试密钥签名；`/data` **没有加密**；内置 root（KernelSU / ReSukiSU），任何你授权了 adb 的电脑都能拿到 root shell；
  从这一版起 SELinux 是 `enforcing`，但手动分区的盘可能要给 EFI 分区改个名（见上文）；启动链未上锁。v0.7.1 及以前免授权的网络 adb：见上面的安全公告。
* **随镜像分发的专有组件**：华为固件与传感器配置、华为 Histen 音频引擎、Google 应用（MindTheGapps）。
* **不支持**：设置里的"清除所有数据"（见"已知问题"；请用图形安装器的*重新安装 Android*）；USB 传文件（MTP）；U 盘；
  指纹（开发中）；手写笔（M-Pencil）；自动亮度；GPS / 定位；DRM 视频（没有 Widevine）；通话时蓝牙耳机和有线耳机的麦克风；
  待机时的消息推送；Google 认证（登记一次即可；Play Integrity 永远过不了）；没有国内应用商店；没有蜂窝网络；没有指南针。
* **其它问题**：长时间运行后音频和蓝牙可能一起卡死；插电脑时平板可能反过来给电脑充电；USB-C 口回插后可能坏掉、直到重启；
  手掌压在屏上会碎成好几个触点；《英雄联盟手游》点开就退；用低功率电源时显示"正在充电"、电量却在掉；
  打开热点会断开 Wi-Fi（这一版带了修复，见"Wi-Fi"一节，还没测）。中文输入法（fcitx5）已预装，但要在设置里自己打开一次。
