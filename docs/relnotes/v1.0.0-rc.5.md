## Upgrade and installation notes

* **System update (OTA)**: users on `v1.0.0-rc.3` and `v1.0.0-rc.4` can update directly under *Settings → System → System update*. Back up important data beforehand: once the new build boots successfully, rolling back to the previous version with user data kept is not supported. Users still on Android 16 (`v0.7.1-alpha`, `v1.0.0-rc.1` and `v1.0.0-rc.2`) will not receive this update through System update (it does not take Android 16 straight to 17); please reinstall with the installer (this erases data).
* **Display orientation and default display size changes**: the system's natural orientation is now landscape, and portrait-only apps appear centered in landscape by default (you can make an app fill the screen under *Settings → Apps → Aspect ratio*; if you previously ran `wm set-ignore-orientation-request` manually, run `adb shell wm set-ignore-orientation-request reset` after updating). The default display density is raised from 240 to 280 (~17% larger on devices with default display size); adjust it under *Settings → Display → Display size* or *Developer options → Smallest width* (`1067` dp matches the earlier 240 density).
* **Fresh installation**: use [Windows installer 0.2.1](https://github.com/vahiru/gaokun-android/releases/tag/windows-installer-v0.2.1) to install dual-boot or create installation media from Windows, or boot [Live installer 0.2.0 (v1.0.0-rc.5)](https://github.com/vahiru/gaokun-android/releases/tag/live-installer-v0.2.0-for-v1.0.0-rc.5) directly. See the [installation guide](https://github.com/vahiru/gaokun-android/blob/v1.0.0-rc.5/docs/INSTALL.md), [known limitations](https://github.com/vahiru/gaokun-android/blob/v1.0.0-rc.5/docs/known-limitations.md), and [FAQ](https://github.com/vahiru/gaokun-android/blob/v1.0.0-rc.5/docs/FAQ.md) before installing.

## Changes

### Display and windowing

* **Natural landscape orientation and portrait-app handling** ([#158](https://github.com/vahiru/gaokun-android/pull/158), [#162](https://github.com/vahiru/gaokun-android/pull/162)): switched the panel's natural orientation to landscape (landscape with the keyboard attached is now the default orientation), updated touch, stylus, accelerometer, camera, and side-fingerprint indicator coordinates accordingly, and automatically migrated any saved rotation lock on upgrade; also corrected the panel's physical millimeter dimensions so apps read the real ~245 dpi. Portrait-only apps now appear centered in landscape instead of forcing the entire screen into portrait, and can be set to full screen per app under *Settings → Apps → Aspect ratio*; landscape-only apps and full-screen video still rotate the screen to landscape.
* **Force activity embedding (experimental)** ([#159](https://github.com/vahiru/gaokun-android/pull/159), [#162](https://github.com/vahiru/gaokun-android/pull/162)): added *Settings → Apps → Force activity embedding (experimental)* to show app pages side by side in landscape using the split layouts bundled in apps, displaying live snapshots of both panes while dragging the divider and automatically expanding to full screen when the right-hand page requests landscape (such as full-screen video). *Note: disabled by default and lists only apps that include split layouts; permission dialogs may be partly covered by the right-hand page, and some cases such as WeChat's main chat list or full-screen playback from the left pane remain limited — see [known limitations](https://github.com/vahiru/gaokun-android/blob/v1.0.0-rc.5/docs/known-limitations.md#showing-app-pages-side-by-side-is-experimental).*
* **Default display density adjusted to 280** ([#168](https://github.com/vahiru/gaokun-android/pull/168)): increased default `ro.sf.lcd_density` from 240 to 280 (~17% larger on devices with default display size; existing custom settings are kept) for more comfortable viewing on a tablet; scaling can be changed under *Settings → Display → Display size* or *Developer options → Smallest width* (`1067` dp matches the earlier 240 density).

### Hardware video encoding and decoding

* **HEVC Main 10 / HDR10 encoding and up to 3 concurrent encoders** ([#188](https://github.com/vahiru/gaokun-android/pull/188), [#190](https://github.com/vahiru/gaokun-android/pull/190), [#194](https://github.com/vahiru/gaokun-android/pull/194), [#202](https://github.com/vahiru/gaokun-android/pull/202)): added HEVC Main 10 and HDR10 hardware encoding; raised concurrent hardware encoding sessions from 1 to up to 3 (both camera recording and the built-in screen recorder use hardware encoding); fixed chroma misalignment at sizes such as 640×480 and removed redundant periodic I-frames between IDRs. *Note: only HEVC supports 10-bit encoding; HLG and P3-D65 colour metadata are written only to the container, and `RGBA_1010102` input is not supported; all active codec sessions fail together on firmware reload, and an occasional no-output encode immediately after wake-up is still under investigation.*
* **Screen-off encoding stability, 444 MHz core clock cap and decoder fixes** ([#141](https://github.com/vahiru/gaokun-android/pull/141), [#189](https://github.com/vahiru/gaokun-android/pull/189), [#191](https://github.com/vahiru/gaokun-android/pull/191), [#192](https://github.com/vahiru/gaokun-android/pull/192), [#193](https://github.com/vahiru/gaokun-android/pull/193), [#195](https://github.com/vahiru/gaokun-android/pull/195), [#196](https://github.com/vahiru/gaokun-android/pull/196), [#197](https://github.com/vahiru/gaokun-android/pull/197), [#198](https://github.com/vahiru/gaokun-android/pull/198), [#199](https://github.com/vahiru/gaokun-android/pull/199), [#200](https://github.com/vahiru/gaokun-android/pull/200); [#134](https://github.com/vahiru/gaokun-android/issues/134)): prevented video hardware hangs when recording, exporting or compressing video with the screen off while awake; capped the video core clock at 444 MHz to eliminate occasional dropped encoded frames; constrained decoder IOVAs outside the content-protection range and shrank input buffers to prevent full-board resets during concurrent decoding; updated advertised decoder frame rates and levels from hardware measurements (including VP9 5.1/5.2 and H.264 1440p@120), fixed DCI-P3 primaries mapping, bit-depth changes after flush, teardown errors, poll busy-loops and firmware error recovery; allowed crash-dump syscalls in the Codec2 HAL seccomp policy so `adb bugreport` no longer terminates it.

### Camera and flashlight

* **All four front and rear camera modules supported, with S5K3L6 PDAF** ([#156](https://github.com/vahiru/gaokun-android/pull/156), [#184](https://github.com/vahiru/gaokun-android/pull/184), [#185](https://github.com/vahiru/gaokun-android/pull/185), [#186](https://github.com/vahiru/gaokun-android/pull/186); [#139](https://github.com/vahiru/gaokun-android/issues/139)): added a board camera module prober so a single image automatically probes and enables both front modules (Hynix HI846 / Samsung S5K4H7) and both rear modules (OmniVision OV13B10 / Samsung S5K3L6), with full-resolution phase-detection autofocus on S5K3L6. *Note: S5K3L6 tuning is taken from the Windows driver and edges of uniform white surfaces may look slightly greenish; its PDAF step scale and S5K4H7 units probed via the new module prober still need further hardware verification.*
* **Flashlight brightness levels** ([#148](https://github.com/vahiru/gaokun-android/pull/148); [#108](https://github.com/vahiru/gaokun-android/issues/108)): added 20 brightness levels (10–200 mA) for the rear torch, controllable via the slider in the Flashlight Quick Settings tile.

### Fingerprint

* **In-app biometric verification and fingerprint-bound keys** ([#133](https://github.com/vahiru/gaokun-android/pull/133), [#180](https://github.com/vahiru/gaokun-android/pull/180)): upgraded the fingerprint HAL to report `STRONG` and issue real authentication tokens, enabling fingerprint authentication inside apps (such as account sign-in and password managers) and fingerprint-bound Android Keystore keys in addition to screen unlock; also fixed FocalTech (`FTE7001`) enrolment becoming unresponsive and failing to retry after sensor errors. *Note: fingerprint payment in WeChat Pay, Alipay and similar apps that rely on manufacturer TEE keys still does not work, and some banking apps may refuse a software-backed key store; FocalTech pixel-pitch calibration is still pending, so enrolment may require more touches.*

### Thermal, performance and power scheduling

* **On-board thermistor throttling, passive cooling and Performance mode** ([#160](https://github.com/vahiru/gaokun-android/pull/160), [#161](https://github.com/vahiru/gaokun-android/pull/161), [#171](https://github.com/vahiru/gaokun-android/pull/171), [#177](https://github.com/vahiru/gaokun-android/pull/177), [#179](https://github.com/vahiru/gaokun-android/pull/179)): enabled CPU and GPU throttling on the four on-board thermistors following the Windows ACPI passive cooling formula and reported them as `SKIN` temperatures to Android; added a **Performance mode** toggle under *Settings → Battery* to raise temperature limits during sustained heavy workloads. When hot, maximum screen brightness is automatically capped by the highest severity across `sys-therm2`–`4` (~78% at `MODERATE`, ~56% at `SEVERE` and above; HDR content is unaffected).
* **New Power HAL and power-source-aware scheduling** ([#163](https://github.com/vahiru/gaokun-android/pull/163), [#165](https://github.com/vahiru/gaokun-android/pull/165), [#172](https://github.com/vahiru/gaokun-android/pull/172), [#173](https://github.com/vahiru/gaokun-android/pull/173)): switched to `lineage-libperfmgr` as the Power HAL for touch, app-launch, and game-loading boosts, ADPF frame-time-based scheduling, and Battery Saver frequency caps, stopping real-time threads from pinning whole CPU clusters to maximum frequency; fixed `system_server` permissions for moving app processes between cgroups. Adopted Windows-aligned policies for AC vs. battery power: plugging in raises minimum CPU frequencies and lifts background and unfocused-window caps, while running on battery caps background and distant freeform windows to save power.

### Bluetooth, audio and settings cleanup

* **Bluetooth headset voice calls** ([#174](https://github.com/vahiru/gaokun-android/pull/174); [#107](https://github.com/vahiru/gaokun-android/issues/107)): enabled the HFP software data path so Bluetooth headsets can handle both playback and microphone capture during calls. *Note: verified for two-way audio on an mSBC wideband headset; real calling apps (such as WeChat voice calls or online meetings), CVSD-only narrowband headsets, and switching audio back to the tablet from the headset mid-call have not been tested yet.*
* **Reorganized device settings and notifications** ([#176](https://github.com/vahiru/gaokun-android/pull/176), [#178](https://github.com/vahiru/gaokun-android/pull/178)): moved the *Detachable keyboard* toggle under *Settings → Connected devices*; replaced *Touch feel* with *Settings → Display → Accidental touch protection* and a *Touch protection* Quick Settings tile; grouped *Speaker sound effects* (now a single-choice dialog) and *Microphone noise suppression* under the *Advanced* section of *Settings → Sound & vibration*; removed the standalone launcher icon from the app drawer; simplified and aligned USB-C and boot-entry notifications.

### Games and graphics

* **Per-app GPU driver compatibility and Unreal Engine fixes** ([#151](https://github.com/vahiru/gaokun-android/pull/151), [#164](https://github.com/vahiru/gaokun-android/pull/164); [#33](https://github.com/vahiru/gaokun-android/issues/33)): added *Settings → System → GPU driver compatibility* to report a Qualcomm driver version in `GL_VERSION` for selected apps, fixing startup exits in Vulkan-only Unreal Engine games such as *Infinity Nikki* (*do not enable it for browsers, or some WebGL pages will not display correctly*); backported upstream Mesa fixes preserving infinities and signed zeros to fix all-black 3D rendering in *Infinity Nikki*. *Note: neither fix has been fully tested in-game yet.*
* **WeChat LiteApp freeze, *Genshin Impact* water and undefined shader values** ([#155](https://github.com/vahiru/gaokun-android/pull/155), [#169](https://github.com/vahiru/gaokun-android/pull/169), [#207](https://github.com/vahiru/gaokun-android/pull/207); [#131](https://github.com/vahiru/gaokun-android/issues/131)): worked around WeChat's Flutter engine waiting twice on the same acquire semaphore, fixing blank Official Account / Game Center pages and ANRs when leaving them; forced depth store on *Genshin Impact* under tiled rendering to fix water disappearing on some frames and objects behind bushes showing in front (*in-game verification pending*); fixed Turnip leaving stale values in some uninitialized shader variables, which caused black areas and rendering corruption in some apps.
* **GPU reliability, DDR bandwidth and gamepad support** ([#142](https://github.com/vahiru/gaokun-android/pull/142), [#152](https://github.com/vahiru/gaokun-android/pull/152), [#167](https://github.com/vahiru/gaokun-android/pull/167); [#101](https://github.com/vahiru/gaokun-android/issues/101), upstream GPU kernel fixes by **Xilin Wu**): backported GPU SMMU context-fault interrupt and DDR peak-bandwidth vote fixes and removed the temporary `smmustall` polling service so DDR bandwidth scales with GPU frequency under heavy load; enabled kernel joystick/gamepad drivers for wired Xbox controllers and similar peripherals.

### Memory, connectivity and system fixes

* **Memory management and smoothness improvements** ([#149](https://github.com/vahiru/gaokun-android/pull/149), [#150](https://github.com/vahiru/gaokun-android/pull/150), [#166](https://github.com/vahiru/gaokun-android/pull/166), [#167](https://github.com/vahiru/gaokun-android/pull/167)): enabled zram swap via `mmd` (half of physical RAM, LZ4); disabled the automatic compaction of all system processes 20 minutes after boot, eliminating ~1 s frame drops and speaker crackles mid-game; aligned transparent huge pages (`madvise`), MGLRU page reclaim, uclamp buckets, and scheduler/diagnostic options with Android GKI.
* **Wi-Fi, USB-C, lock screen charging info and platform fixes** ([#132](https://github.com/vahiru/gaokun-android/pull/132), [#135](https://github.com/vahiru/gaokun-android/pull/135), [#143](https://github.com/vahiru/gaokun-android/pull/143), [#146](https://github.com/vahiru/gaokun-android/pull/146), [#153](https://github.com/vahiru/gaokun-android/pull/153), [#154](https://github.com/vahiru/gaokun-android/pull/154), [#175](https://github.com/vahiru/gaokun-android/pull/175), [#181](https://github.com/vahiru/gaokun-android/pull/181), [#183](https://github.com/vahiru/gaokun-android/pull/183); [#102](https://github.com/vahiru/gaokun-android/issues/102), PCIe coherency patch by **Xilin Wu**): switched Wi-Fi board data to `HW_GK3` (unlocking 2.4 GHz channels 12 and 13), forwarded framework country codes to the WCN6855 firmware with bundled `regulatory.db`, and fixed APs started after boot not appearing in Wi-Fi scans; moved USB role handling and the computer-connected wake lock into the USB port HAL, added up to 5 automatic retries on USB-C (UCSI) boot initialization timeouts (~15 s delayed port availability on affected boots) and acknowledged repeated EC USB events after a final failure so sleep is not blocked; fixed lock screen charging current, wattage, voltage, temperature and "Charging rapidly" display; enforced cache-coherent PCIe transactions on SC8280XP; reduced repeated extra-cursor-plane warnings in display logs.
* **Wi-Fi Direct** ([#208](https://github.com/vahiru/gaokun-android/pull/208)): enabled Wi-Fi Direct; find and connect to phones and other Wi-Fi Direct devices in *Settings → Network & internet → Internet → Network preferences → Wi-Fi Direct*, while the tablet stays connected to Wi-Fi. *Note: Wi-Fi Direct cannot be used while the hotspot is enabled, and in some countries and regions groups created by the tablet cannot use the 5 GHz band — see [known limitations](https://github.com/vahiru/gaokun-android/blob/v1.0.0-rc.5/docs/known-limitations.md#wi-fi-direct-limitations).*
