Android 16 (crDroid) for the **Huawei MateBook E Go** (Snapdragon 8cx Gen 3 /
SC8280XP) on a **mainline Linux kernel**, with hardware Vulkan on the Adreno 690.

A bug-fix release: **standby no longer hangs the machine**, the **Wi-Fi hotspot
works**, apps that use USB stop crashing, and **rhythm games stay in sync** with
their music.

**Talk to us:** [Telegram](https://t.me/gaokunAndroid) · QQ group **920133252**

> ### ⚠️ Alpha
> A fresh install **erases the internal disk** (unless you use the graphical
> installer's dual-boot mode), and no image of the factory state exists anywhere.
> You should be comfortable recovering a machine that will not boot. No warranty.
>
> Any BIOS version works. Secure Boot must be off.

## Standby

**Waking from standby could hang the machine for good** — black screen, only a
long press of the power button helped ([#16](https://github.com/vahiru/gaokun-android/issues/16),
thanks to **@niceboat0** for the complete crash log). Three things lined up:

* On every wake the Wi-Fi chip is powered back up and its firmware reloaded,
  which needs several large blocks of contiguous memory below 4 GB — and memory
  cannot be defragmented while the machine is waking. After a long uptime those
  blocks were sometimes not there, and Wi-Fi failed to start.
* A debugging setting had been left in the kernel: if any device took more than
  10 seconds to wake, the kernel gave up and crashed on purpose. A Wi-Fi chip
  that failed to start triggered exactly that.
* After a crash, the kernel waited forever instead of restarting.

All three are fixed. The Wi-Fi driver now keeps its firmware buffers through
standby instead of giving them up and asking again, and the memory pool reserved
for exactly this kind of request (CMA) — which the device tree had placed above
4 GB, out of reach of the Wi-Fi chip — now sits below 4 GB. Over three wakes,
the number of such large memory requests went from 69 to 0. The watchdog is back
to its default 120 seconds, and if the kernel ever does crash it now restarts
after 10 seconds instead of hanging (the crash log is still saved).

Tested on this build: 10 standby/wake cycles, Wi-Fi back within about 2 seconds
each time. The original hang took about 14 hours of uptime to show up, so
reports from long-running machines are very welcome.

## Wi-Fi

* **The hotspot works** ([#11](https://github.com/vahiru/gaokun-android/issues/11),
  thanks to **@niceboat0**). The hotspot service (`hostapd`) had never been
  included. Turning on the hotspot disconnects the machine from Wi-Fi: the chip
  runs either as a hotspot or as a client, not both.
  *Correction (2026-10-04): this is not a chip limit — the driver supports
  STA+AP, the software configuration does not (yet); see
  [docs/known-limitations.md](https://github.com/vahiru/gaokun-android/blob/main/docs/known-limitations.md).*
* **Routers in WPA2/WPA3 mixed mode should connect.** Android upgrades a saved
  WPA2 network to WPA3 when the router offers both, and on such routers the
  connection was rejected. That upgrade is now off; pure WPA3 networks still use
  WPA3. Not tested here (we have no mixed-mode router) — please tell us if it
  works for you.

## Audio

**Rhythm games stay in sync.** Under load the audio driver could skip a whole
block of music (about 85 ms) whenever the game delivered audio a little late,
and it told apps where playback was from what they had sent rather than from what
was actually playing. Games that time notes against the audio clock (Arcaea,
Phigros) saw an offset that was large and kept jumping. Playback is now paced by
the sound hardware itself, nothing is dropped, and the reported position is the
real one. Measured in Arcaea: 7 skipped blocks → 0; with a speaker-to-microphone
loopback the reported timing is about 30 ms more accurate, and after a stall the
very next sound is back in place (before: about 8 seconds of misplaced sounds).
If you calibrated a game's audio offset on an earlier release, calibrate it again.

## USB

**Apps that use USB no longer crash on start** ([#13](https://github.com/vahiru/gaokun-android/issues/13),
thanks to **@niceboat0**). Android's USB service was never started, so asking
for it returned nothing; apps that did not expect that — the China Telecom cloud
desktop (天翼云电脑) among them — crashed immediately. Apps should now also be able to
use USB devices plugged into the machine (with the usual permission prompt). We
checked that the service runs and lists connected devices; we have not run the
cloud desktop app itself.

## Smaller things

* **System updates on dual-boot or hand-partitioned disks**: when the disk has
  both a Windows boot partition and a separately named one for Android, the
  update could pick the wrong one. It now checks which one actually holds the
  Android boot entries. (Not yet tested on a real dual-boot machine.)
* SELinux: another round of rules and labels towards enforcing. Disks set up by
  the graphical installer now get correct partition labels, and the camera works
  in an enforcing trial. The system still runs `permissive`.

## Known issues

* SELinux is still `permissive`.
* **League of Legends: Wild Rift** closes right after launch (reported, no log
  yet). If you can, send `adb logcat -b crash` from right after it closes.
* No auto-brightness. The light sensor answers on the bus, but activating it
  crashes the sensor DSP, so it stays off.
* *Erase all data* (factory reset) in Settings does not work — this machine has
  no working recovery. Use the graphical installer's *Reinstall Android* instead.
* Audio (and Bluetooth) can deadlock after long uptime; a watchdog records the
  evidence under `/data/vendor/gaokun3/hangdump-*` — please attach it if you hit
  this.
* A palm resting on the screen fragments into several touches.
* Rear camera image quality is not tuned yet: no colour calibration, dim scenes
  are noisy, flash shots overexpose; autofocus in the dark is slow.
* Hardware video **encoding** is still off.
* **After replugging, the USB-C port can stop working** (no USB adb, no USB
  devices) until a reboot. Unchanged from v0.7.0.
* Wi-Fi gets a new MAC address on every boot, so routers see a "new device"
  each time.

## Files

The in-system updater will offer this build; nothing here is needed for a normal
update. For a **fresh install** you want `super.img.zst` and `boot.img`.

| File | What |
|---|---|
| `crDroidAndroid-16.0-20261003-gaokun3-v12.11.zip` (1.26 GiB) | OTA package, also what the in-system updater downloads |
| `super.img.zst` (1.20 GiB) | system / system_ext / product / vendor, for a fresh install |
| `boot.img` (27.5 MiB) | kernel + device tree + first-stage ramdisk |
| `install-artifacts.sha256` | checksums of the three files above |
| `gaokun3.json` | the updater manifest for this build |

Build stamp `1791053208`, incremental `20261003184648`. The checks above were run
on a machine running exactly this build. Not run on it: a phone actually joining
the hotspot, a WPA2/WPA3 mixed-mode router, the cloud desktop app, and a real
