# 已知限制与不支持的功能

[**English → known-limitations.md**](known-limitations.md) · [常见问题](FAQ.zh-CN.md) · [安装](INSTALL.zh-CN.md)

本系统运行在一台没有任何厂商Android支持的机器上。下面列出安装之前应当了解的事项：有些是有意做出的取舍，有些是尚未完成的功能，有些受限于这台机器本身。

每一条按同样的格式说明：**现象**（你会遇到什么）、**原因**、**建议**（目前可以怎么做）。某一版特有的问题，见那一版的[发版说明](relnotes/)。

## 一、安全与隐私（请先阅读这一节）

### v0.7.1及更早的版本开放了无需授权的网络adb
* **现象**：使用时看不出任何异常。
* **原因**：v0.7.1及更早的版本会在所有网络接口（包括Wi-Fi热点）上开放TCP 5555端口的adb，连接时不需要授权，连接后可以取得root权限，镜像中还带有维护者的adb公钥。与你连接同一个Wi-Fi、或连接你热点的任何人，都可以完全控制这台机器。从1.0.0-rc.1起，adb默认关闭，每台电脑都需要你授权，不再开放5555端口，也不再带有维护者的公钥。通过系统更新升级后即自动生效。
* **建议**：
  * 仍在使用v0.7.1或更早版本的，请先备份，再在"设置 → 系统 → 系统更新"中更新。从Android 16升级到17会改写用户数据且无法回退，详见[rc.3发版说明](relnotes/v1.0.0-rc.3.zh-CN.md)。更新之前，请不要连接不信任的Wi-Fi，也不要让陌生人连接你的热点。
  * 如果曾经手动设置过`persist.adb.tcp.port`，这个设置在更新后仍会保留，清除方法尚未整理。
  * 需要通过网络使用adb时，请使用[无线调试](FAQ.zh-CN.md#无线调试)。

### 系统使用AOSP公开的测试密钥签名
* **现象**：使用时看不出来。系统版本信息中显示的`release-keys`只是一个标签。
* **原因**：系统、系统应用和OTA更新包都使用AOSP源码中公开的测试密钥签名，对应的私钥任何人都能下载。因此任何人都能制作出本机会接受的OTA更新包，或以系统身份运行的应用。这台机器的安全取决于下载渠道的可靠，以及你不安装来源不明的"系统组件"。
* **建议**：
  * 只通过设置中的系统更新，或本项目的GitHub发布页更新系统。
  * 不要安装别人发来的、自称"系统补丁"或"系统组件"的APK或zip文件。
  * 全新安装时，安装器会先核对`install-artifacts.sha256`再写入硬盘，请不要跳过这一步。

### 用户数据没有加密
* **现象**：锁屏密码只能阻止别人直接使用这台机器，无法阻止别人读取其中的数据。
* **原因**：用户数据分区是未加密的ext4文件系统。Secure Boot必须关闭，开机菜单中有安装器和救援系统，在机器前以root登录不需要密码；插入一个Linux U盘也能读取硬盘。拿到机器的人可以直接读出照片、聊天记录、浏览器登录状态、Wi-Fi密码等全部数据。
* **建议**：
  * 请把这台机器当作"拿到机器即可读取全部数据"的设备来使用，不要在上面存放敏感资料。
  * 出售、送修或借给别人之前，请用图形安装器的"重新安装Android"清除数据，见[常见问题](FAQ.zh-CN.md#清除数据)。
  * 将来如果加入文件级加密，需要清除数据后重新安装，无法通过系统更新直接获得。

### 内核内置root（KernelSU / ReSukiSU）
* **现象**：内核内置KernelSU（ReSukiSU分支），部分银行、支付应用和带反作弊的游戏可能检测到它，提示"设备存在风险"或拒绝运行。
* **原因**：开发和排查问题需要root，因此发布版本也保留了它。哪些应用能取得root权限，由ReSukiSU管理器决定：只有在管理器中批准过的应用才能取得；没有安装管理器时，任何应用都无法取得。
* **建议**：
  * 不需要root时，不要在管理器中为任何应用授权。
  * 在管理器中开启adb root后，授权过USB调试或无线调试的电脑通过`adb shell`即可直接取得root权限。不需要时请不要开启adb root；只授权你信任的电脑，不使用时关闭USB调试和无线调试。
  * 目前没有不带root的版本，内核中的root功能无法关闭。
  * 在冒烟测试中，使用ACE反作弊的《三角洲行动》和《卡拉彼丘》可以正常运行；银行和支付类应用尚未经过系统的测试，欢迎反馈。

### SELinux为enforcing模式，手动分区的硬盘可能需要给EFI分区改名
* **现象**：大多数机器上看不出来。但如果硬盘是你自己手动分区的，并且EFI分区的GPT分区名既不是`esp`，也不是`EFI system partition`，系统更新和切换槽位都会失败。
* **原因**：从1.0.0-rc.1起，SELinux从permissive（只记录、不拦截）改为enforcing（实际拦截）。SELinux是Android应用沙箱的第二层防护，即使某个应用找到了漏洞，能做的事也少得多。安全规则只允许系统更新和启动控制组件按这两个名称打开EFI分区：`esp`是安装器"清除整个磁盘"时建立的名称，`EFI system partition`是Windows建立的名称，双系统使用的就是它。早期版本在找不到时会扫描所有存储设备，enforcing模式下不允许这样做。
* **建议**：
  * 如果你的EFI分区使用了其他名称，请在任意Linux中（安装器的终端或救援系统均可）改一次名：`sgdisk -c <N>:esp /dev/nvme0n1`，其中N是EFI分区的分区号。UEFI只看分区类型，改名不会有副作用。安装器检测到这种名称时也会提醒。
  * 如果某项功能在v0.7.1上正常、现在无法使用，请报告问题，并附上`adb shell dmesg | grep avc`的输出。

### 启动链未锁定，系统分区不做完整性校验
* **现象**：开机时不会检查系统是否被改动过，Play Integrity无法通过（见下文"未通过Google认证"）。
* **原因**：这台机器通过UEFI和systemd-boot启动，Secure Boot必须关闭，内核没有签名，也没有启用dm-verity。能在这台机器上安装其他系统，正是依靠这条开放的启动链。
* **建议**：无法规避，这是在这台机器上运行Android的前提。

### 应用读取到的内核版本不是真实版本
* **现象**：应用读取到的内核版本是`6.6.30-android15-8-g0a4d3c12b3`，这个版本号不对应任何真实的Android内核，实际运行的是主线Linux 7.2.9加本项目的补丁。在1.0.0-rc.2和rc.3上，整个系统都报告这个版本号；从1.0.0-rc.4起，只有应用读取到它，`adb shell`中的`uname -r`和设置中显示的内核版本都是真实版本。
* **原因**：部分应用的环境检测只接受Android通用内核的版本号。这里只改变应用读取到的数字，内核本身、编译时的版本号和模块校验都没有改变。这是有意的伪装，因此在这里说明。
* **建议**：从1.0.0-rc.4起，可以在"设置 → 系统 → 内核版本伪装"中关闭或修改，重启后生效。1.0.0-rc.2和rc.3没有这个设置，需要查看真实版本时，以root权限运行`dmesg | head -1`。请不要使用KernelSU管理器中的"安装"或LKM修补功能，本机的KernelSU已经编入内核。

## 二、不支持或不完整的功能

### 设置中的"清除所有数据"尚未经实测
* **现象**：设置中的"清除所有数据（恢复出厂设置）"会在重启后由fastboot模式执行，但这一流程尚未在实机上测试，无法保证数据会被完整清除。
* **原因**：这一功能原本需要Android recovery来执行，而recovery在这台机器上无法启动，因此改由开机菜单中的fastboot模式代为执行。
* **建议**：请用图形安装器的"重新安装Android"清除数据，它默认清除用户数据，步骤见[常见问题](FAQ.zh-CN.md#清除数据)。

### 通过USB传输文件时没有提示，速度只有USB 2.0
* **现象**：连接电脑后，平板上不会弹出"USB用途"的通知。需要传输文件时，请在"设置 → 已连接的设备 → USB"中选择"文件传输"或"PTP"，电脑上随后会出现名为"MateBook E Go"的便携设备。同一页面中还有"USB网络共享"和"MIDI"。传输速度只有USB 2.0的水平，约30 MB/s。
* **原因**：键盘盖的接口在系统中是一个始终连接着的USB键盘，Android检测到这类设备时不显示USB连接的通知。靠近电源键的USB-C口在连接电脑时只能以USB 2.0速度工作。
* **建议**：按上面的路径在设置中选择"文件传输"。连接电脑时平板不会进入待机，息屏后传输不会中断；传输完成后请拔下数据线。

### 指纹仅能用于锁屏解锁，无法用于支付
* **现象**：1.0.0-rc.3及更早的版本不支持指纹。从1.0.0-rc.4起，可以在设置中录入指纹并解锁屏幕（支持Goodix与FocalTech两种传感器），但银行、支付类应用的指纹支付以及需要密钥库认证的应用指纹登录无法使用；配备FocalTech传感器的机器上，识别效果未经实测。
* **原因**：指纹的图像解码、匹配和模板存储运行在普通系统服务中，没有硬件密钥签名和防伪认证，因此向系统申报最低的便利级（Class 1），高安全要求的应用不会调用它。FocalTech传感器的像素间距比例还未用真实手指测量。
* **建议**：在支付等应用中继续使用密码验证。如果FocalTech机器上识别率偏低，请先使用PIN或密码解锁，并在issue中反馈。

### 手写笔不支持一代M-Pencil
* **现象**：1.0.0-rc.1及更早的版本中，手写笔完全没有反应。从rc.2起，二代和三代M-Pencil可以使用压感、悬停、倾斜和侧边双击，三代笔的日常使用效果尚未经实测。一代M-Pencil无法使用。
* **原因**：手写笔的信号来自触摸屏的第二块控制芯片，驱动由社区贡献者逆向实现；一代笔使用另一种协议，驱动不支持。
* **建议**：如果二代或三代笔在rc.2或之后的版本上无法正常工作，请提交问题，并附上`adb shell getevent -pl`的输出。

### 定位基本无法使用
* **现象**：地图、天气、外卖、打车等应用无法取得位置，或一直显示"定位中"。
* **原因**：这台机器没有GPS。网络定位由Google Play服务提供，在中国大陆无法连接Google时不可用。
* **建议**：
  * 在天气等应用中手动选择城市。
  * 自带定位功能的国内应用（例如使用Wi-Fi定位的地图应用）也许可以定位，尚未经实测。
  * 导航请使用手机。

### 无法播放受DRM保护的视频
* **现象**：Netflix、Disney+、Prime Video等无法播放正片，会提示DRM错误或"设备不支持"。国内视频应用的部分会员或版权内容可能也会受到影响，尚未经实测。
* **原因**：系统中没有任何DRM模块。Widevine是Google的闭源组件，需要授权和认证，本项目无法附带。
* **建议**：请在其他设备上观看这类内容。

### 通话时无法使用蓝牙耳机的麦克风
* **现象**：用蓝牙耳机进行微信语音、腾讯会议或游戏语音时，耳机上的麦克风无法工作，通话声音也可能不从耳机播放。有线耳机上的麦克风尚未经实测。
* **原因**：蓝牙通话需要一条专门的音频通路，这台机器没有高通为手机提供的那一套，系统中尚未实现替代方案。
* **建议**：通话时请使用平板自带的麦克风和扬声器。用蓝牙耳机听音乐使用的是另一条通路，不受影响。

### 待机时部分应用的消息会延迟
* **现象**：屏幕关闭、机器进入待机后，微信、QQ等不使用Google推送（FCM）的应用，新消息要等到系统下一次定时唤醒或你点亮屏幕时才会收到，通常延迟一两分钟，偶尔三分钟左右。使用FCM的应用，在1.0.0-rc.3及更早的版本上同样会延迟，从1.0.0-rc.4起可以唤醒系统、及时收到消息。待机期间Wi-Fi保持连接，唤醒后不需要重新连接。
* **原因**：国内应用在这个系统上没有可用的厂商推送通道，只能在系统醒来时自行连接服务器收取消息。
* **建议**：需要及时收到消息时，请让屏幕保持常亮，或用手机接收消息。

### 未通过Google认证
* **现象**：Play商店提示"此设备未经Play保护机制认证"，部分应用无法安装。依赖Play Integrity的应用（例如Google钱包、部分海外银行应用）无法使用。
* **原因**：本系统不在Google的认证设备名单中。Play Integrity还要求锁定的启动链和Google签名的系统，这在本机上无法满足。
* **建议**：按[安装说明中的步骤](INSTALL.zh-CN.md#此设备未经play保护机制认证)登记一次，Play商店即可正常使用。Play Integrity无法解决。

### 系统附带Google应用，没有国内应用商店
* **现象**：无法访问Google时，Play商店和Google服务都无法使用，Google服务还会在后台反复尝试连接网络，耗电情况尚未测量。系统中没有国内的应用商店。
* **原因**：本项目只发布附带Google应用的版本。
* **建议**：通过浏览器从应用官网或国内应用商店的网页版下载APK安装。

### 其他不具备的硬件
* **蜂窝网络和SIM卡**：这台机器没有基带。
* **指南针**：没有磁力计。自动旋转使用加速度计和陀螺仪，不受影响。

## 三、尚未解决的问题

以下几条属于缺陷而不是取舍，修复后会从这里删除。

### 长时间运行后，声音和蓝牙可能同时失效
* **现象**：机器连续运行很长时间后，声音和蓝牙同时失效，只有重启才能恢复。这是用户报告的问题，尚未复现。
* **原因**：尚不清楚。音频和蓝牙共用一条通往DSP的通路，推测是这条通路卡住了。
* **建议**：重启即可恢复。系统中有一个监控程序，发现卡死时会自动把相关记录保存到`/data/vendor/gaokun3/hangdump-*`，重启后仍然保留。报告问题时请附上这些记录（需要root权限，命令见[常见问题](FAQ.zh-CN.md#机器能进入android时)）；如果没有这个目录，也请在报告中说明。

### 连接电脑时，平板可能反过来为电脑供电
* **现象**：把平板（靠近电源键的USB-C口）连接到电脑后，电脑和USB调试都识别不到平板，平板的电量反而在下降。
* **原因**：平板和很多电脑的USB-C口都既能供电也能受电。电脑不支持USB PD时，由谁供电在插入的瞬间决定，偶尔会反过来。这时平板成了主机，而电脑不会作为USB设备工作，双方就互相识别不到。
* **建议**：拔下数据线重新插一次（通常一次即可），或换用电脑上的另一个接口。只有靠近电源键的USB-C口可以用于USB调试，另一个口只能连接外设。

### 开机后USB-C口偶尔无法正常工作，直到重启
* **现象**：偶尔在开机后，USB-C口无法正常工作：USB调试无法连接，插入的USB设备也识别不到，直到重启为止。
* **原因**：开机时Type-C控制器（UCSI）偶发初始化失败，原因尚在排查。
* **建议**：重启即可恢复。在此之前，请通过Wi-Fi使用adb和传输文件。

### 屏幕关闭时继续处理视频，视频可能不完整
* **现象**：屏幕关闭后，如果录像、视频导出或发送前的视频压缩还在后台继续，得到的视频可能比预期短，或者中间缺帧。出现过一次之后，录像也可能一直失败，直到重启。
* **原因**：屏幕关闭而系统还没有休眠时，处理器会进入更深的省电状态，视频编码硬件在这期间会卡住，原因尚未查明。亮屏使用时没有这个问题。
* **建议**：录像、导出或压缩视频时请保持屏幕点亮。如果录像一直失败，请重启平板。

### 同时录制两路视频时，第二路较慢，或者第一路被中断
* **现象**：已经在录像时再开始一路录制，第二路的画面可能不流畅。如果第二路由系统发起（例如录像时从快捷设置开始录屏），正在进行的录像可能会中断，这一点尚未经实测。
* **原因**：视频编码硬件同一时刻只能处理一路。第二路通常会自动改用较慢的软件编码；但当发起方的优先级更高时，系统会先把硬件编码器从正在录制的应用那里收回。
* **建议**：尽量一次只录一路。

### 《英雄联盟手游》可以启动，能否进入对局尚未经实测
* **现象**：1.0.0-rc.1及更早的版本中，游戏一打开就退出。从rc.2起可以启动到用户协议页面，能否进入对局尚未经实测。
* **原因**：游戏引擎假设64位进程的内存地址不超过2^39，而这个内核默认提供2^48的地址空间。现在内核默认按2^39分配地址。
* **建议**：如果在rc.2或之后的版本上仍然退出，或卡在其他地方，请在退出后立即获取崩溃日志（见[常见问题](FAQ.zh-CN.md#机器能进入android时)），附到[#15](https://github.com/vahiru/gaokun-android/issues/15)。

### 中文输入法需要手动启用一次
* **现象**：默认的键盘不支持中文。
* **原因**：从1.0.0-rc.1起预装了中文输入法fcitx5（带拼音、双拼和五笔），但没有设为默认输入法。
* **建议**：在"设置 → 系统 → 键盘 → 屏幕键盘"中打开Fcitx5，再切换到它。以后请从fcitx5-android的GitHub发布页更新，F-Droid版本的签名不同，无法覆盖安装。使用实体键盘时如何切换中英文，尚未整理。
